# Slice viewer — evaluation and refactor recommendations

**Status:** RECOMMENDATIONS ONLY (2026-08-05); no code changes made.
**Decision (Greg, 2026-08-05):** mbirjax's viewer stays as-is for now; the
restructured viewer is built greenfield into mbirtorch instead (see
`mbirtorch_viewer_build.md`), with an mbirjax retrofit after field use.
Produced by a dedicated evaluation agent at Greg's request, against three
questions: a more modern GUI framework?  simpler event handling?  other
refactor recommendations.  Constraints applied: stable on macOS and Linux
(Windows optional), the remote ThinLinc/X11 cluster use, a headless-silent
import, install friction for scientist users, and a pure-numpy viewer that
serves both mbirjax and the mbirtorch port.

**Headline:** stay with matplotlib but RESTRUCTURED (model/view split, no
import-time backend forcing, easygui deleted, blitting for remote-X slider
lag); PySide6 + pyqtgraph as an optional later frontend on the same extracted
model.  The eight-step refactor sequence at the end keeps the viewer working
at every step; steps 2, 6, and 7 are the cluster- and port-load-bearing ones.

---


## Current architecture (short)

`mbirjax/viewer.py` (1136 lines) is a single-file, single-class viewer: `SliceViewer` plus the `slice_viewer()` wrapper. At import it forces `matplotlib.use('TkAgg')` (viewer.py:9-17), imports `easygui` unconditionally (viewer.py:5), and freezes backend-dependent module constants `TKAGG`, `Y_SKIP`, `LOAD_LABEL`, `SAVE_LABEL` (viewer.py:49-57). Since `mbirjax/__init__.py:13` does `from .viewer import *` and there is no `__all__` anywhere in the package, `import mbirjax` triggers the backend side effect (the headless-batch-job warning) and re-exports `os`, `gc`, `np`, `plt`, `easygui`, `h5py`, the widget classes, and all viewer constants as `mbirjax.*` names.

Inside the class, everything is mixed: data model (axis permutations, slice indices, difference images, ROI statistics), rendering (figure/axes/colorbar construction, a hand-rolled context menu made of `fig.text` boxes), interaction (four separate `button_press_event` handlers plus motion/release/key handlers holding state in ~8 scattered flags), and I/O (npy/npz/h5 load, h5 save, easygui dialogs). The constructor also *shows* the window (viewer.py:139), so construction and the event loop are conflated; the nonblocking mode (added 2026-07-26, commit 945fdb3) works around this with a module-global `_NONBLOCKING_VIEWERS` registry (viewer.py:1069) and a TkAgg-finalizer teardown dance (`plt.close` by object, `del`, `gc.collect()`; viewer.py:1129-1136).

**Actual API surface** (grep over demo/, docs/, mbirjax/, experiments/ — 40+ call sites): every use goes through `mj.slice_viewer(*volumes, ...)`; nobody constructs `SliceViewer` directly. Kwargs used in practice: `data_dicts` (dict or list), `title` (often multi-line), `vmin`/`vmax`, `slice_label` (str or list), `slice_axis` (int; `0` for sinograms), and `block=False` (demo/demo_10_artifacts.py:204 only). `cmap` and `show_instructions` are never overridden in demo/. One library-internal call: `mbirjax/preprocess/mar.py:875` opens a blocking GUI from inside `recon_plastic_metal` at `verbose >= 2`. The viewer's only intra-package dependencies are `mj.TomographyModel.convert_subdicts_to_strings` (viewer.py:114; defined in tomography_model.py:1194, pure yaml/string code but living in a jax-importing module) and `mj.save_data_hdf5` (viewer.py:831; utilities.py:121, also in a jax-importing module).

## GUI framework options

| | (a) matplotlib, restructured | (b) PySide6 + pyqtgraph | (c) napari | (d) Browser (local server + JS) |
|---|---|---|---|---|
| **mac/linux stability** | Excellent; most battle-tested option. Windows works too. | Good; PySide6 wheels for all 3 OSes incl. mac arm64. | Good locally, but pre-1.0 API churn (0.5.x, npe2/Qt6 transitions). | Excellent (any browser). |
| **Remote display (ThinLinc / ssh -Y)** — load-bearing | Proven: exactly the current deployment. Raster-only; ThinLinc fine, plain X laggy but fixable with blitting (below). | Qt raster over X11 works in ThinLinc; needs system xcb libs on nodes; avoid the optional OpenGL path. Roughly matplotlib-class over plain X. | Worst: vispy needs OpenGL >= 2.1; forwarded/indirect GLX is usually broken or llvmpipe-slow on clusters. | Best: `ssh -L` port-forward, no X at all. Slider UI latency becomes local JS; only ~0.2-1 MB/slice crosses the wire. |
| **Dependency weight / install friction** | Zero new deps, and this path *drops* easygui. | +PySide6 (~100+ MB) + pyqtgraph; solid pip/conda wheels; ship as `mbirjax[viewer-qt]` extra. | Heavy: Qt + vispy + OpenGL + plugin machinery; slow startup. | Zero client deps if stdlib `http.server`+WebSocket; plotly/dash variants add flask/tornado and are sluggish for rapid 1024^2 slicing. |
| **Perf, 1024^3 float32 volumes** | Slice extraction ms-scale; bottleneck is full-figure redraw (~100 ms with colorbars/sliders); blitting gets slice/contrast updates to ~10-20 ms. | Best-in-class 2D: LUT/window-level applied in C, built-in `HistogramLUTItem`, `ImageView` z-slider, linked views (`setXLink/YLink`), real `CircleROI` with handles — much of SliceViewer comes free. | Excellent locally (GPU), irrelevant if it can't render on the cluster. | Fast if hand-rolled (uint8/16-bit tiles); window-level can run client-side. |
| **Maintenance risk** | Lowest; matplotlib is a hard dependency forever anyway. | Low-moderate; pyqtgraph is active and standard in beamline/DAQ circles. Qt6 major-version churn is real but slow. | Highest of the four for this use. | Moderate-high: a second language (JS) and a server lifecycle to own. |
| **Current code survival** | ~70-80% (all model logic, most rendering; event layer rewritten). | Model layer only (~30%); all UI rewritten. | ~10% (thin adapter). | Model layer (~30%); all UI new. |

Also considered: **silx** (ESRF's synchrotron GUI kit; Qt-based `ImageView` + built-in HDF5 browser — attractive for this exact audience, but a bigger, more opinionated stack than pyqtgraph with version-pinning friction; treat as a variant of (b)); **Dear PyGui / vedo / pyvista** (all need GL — same remote problem as napari); hand-rolled tkinter (strictly worse than (a)).

**Recommendation: (a) restructured matplotlib**, with the restructure explicitly producing a pure-numpy model layer and a swappable frontend. Reasoning against the constraints: matplotlib is already a required dependency (pyproject.toml:35), so this is the only option with *negative* install cost (easygui, pyproject.toml:45, gets deleted); the remote-X/ThinLinc story is already field-proven, and blitting addresses the one observed remote complaint (laggy sliders under plain X11); the headless-silent-import fix is orthogonal to framework choice; and the mbirtorch port needs the model/view split regardless of frontend, so it is the no-regret first investment.

**Runner-up: (b) PySide6 + pyqtgraph** as an *optional* frontend (`mbirjax[viewer-qt]`) on top of the same extracted model. If the matplotlib ceiling ever binds (cine-speed scrolling, histogram-based windowing, native context menus — the current fake-menu code is the strongest argument for Qt), that is where to spend, and the model layer transfers unchanged. napari should be at most an optional one-line export (`napari.view_image(vol)`) for users who have it; the browser viewer is the best long-term remote answer but the highest new-code cost — revisit only if plain-`ssh -Y` (non-ThinLinc) usage becomes common.

## Event-handling simplifications

1. **Consolidate the four `button_press_event` handlers into one dispatcher.** `on_context_menu`, `on_context_select`, and `on_press` are all connected to the same event (viewer.py:684-687), plus a fourth, `on_right_click`, connected inside `_add_intensity_slider` (viewer.py:346). They coordinate via registration order and by mutating the event object: `on_context_select` sets `event.menu_option_selected = True` (viewer.py:678) which `on_press` sniffs with `hasattr` (viewer.py:530-531). A single `on_button_press` that hit-tests in a defined order (open menu / menu item / slider axes / ROI) removes the event mutation, the order dependence, and most of the `_tk_button_pressed` swallow-the-next-click hack (viewer.py:134, 311, 534-537).

2. **Replace the scattered flags with one explicit interaction mode.** Current mode is encoded in eight attributes defined in three different places: `_is_drawing` (viewer.py:523, also reset inside the intensity-slider closure at 320 and in `on_key` at 645), `_is_moving`/`_move_offset` (510-511), `_resize_index`/`_resize_anchor` (203-204, 543), `_drag_start` (522), `_image_selection_dict['selecting_image']` (135-136, 141-142), `_tk_button_pressed` (134). A single `self.mode` enum (`IDLE`, `DRAW_ROI`, `MOVE_ROI`, `RESIZE_ROI`, `SELECT_COMPARISON`) with a small payload makes `on_motion` a clean dispatch instead of the interleaved tooltip-plus-drag if/elif chain (viewer.py:581-597 tooltips woven through 600-623 drag logic). Concrete fragility this fixes: the zoom-sync callbacks are connected during `_draw_images` (viewer.py:267-268) but read `self._syncing_limits`, which is not assigned until *after* `_build_figure` returns (viewer.py:132) — a latent construction-order `AttributeError` should `_update_axis` ever change a perm during setup. Initialize one state object before any wiring.

3. **Fix `_update_slice`'s dead arithmetic and add a change short-circuit.** Lines 440-442 compute `frac = new_slice / d.shape[2]; idx = int(round(frac * d.shape[2]))` — an identity round-trip, so volumes shallower than the slider max just clip at their last slice instead of the proportional mapping that `_update_axis` uses (viewer.py:415). Either index directly or implement the intended proportional map — currently two inconsistent behaviors. Also: the slider emits continuous floats, so every mouse motion re-runs `set_data` + title + `draw_idle` for all volumes even when the rounded index is unchanged; add `if idx == self.cur_slices[i]: continue` and/or `valstep=1` on the `Slider` (viewer.py:286-288). With `valstep=1`, hide the slider for single-slice volumes instead of the `VALMAX_EPS` epsilon hack (viewer.py:47, 285, 398-402).

4. **`_display_mean`: missing `continue` and a throttle that drops the final update.** The guard `if circle is None or self._is_drawing or self._is_moving:` only hides the tooltip and then falls through to `x, y = circle.center` (viewer.py:476-478) — an `AttributeError` if any circle is ever `None` while others are not (works today only because circles are created all-or-none at 568-571). Separately, the 0.3 s time-gate (viewer.py:469-472) has no trailing edge: `on_release`'s final `_display_mean()` (viewer.py:635) is silently swallowed when it lands inside the window, leaving stats stale at the pre-release position. Fix: `continue`, plus either a `force=` parameter used on release or a trailing one-shot `fig.canvas.new_timer`.

5. **Tooltips are built twice and leak artists.** `_draw_images` creates `self.tooltips` (viewer.py:271-280) and `_connect_events` immediately recreates them (viewer.py:512-521); both run at startup (198, 202), leaving the first set as orphaned invisible annotations on the axes. Give the rebuild path sole ownership; `_connect_events` should own callbacks only.

6. **Stop using full teardown/rebuild as the universal refresh.** `_update_axis` mutates image data, limits, and title in place (viewer.py:424-429) and then calls `_draw_images()` (430), which removes and recreates every axis, colorbar, and tooltip — so 424-429 is dead work (including the `axes_perms[0]`-instead-of-`[i]` title bug at 429, which is masked only because it's overwritten). `_on_reset` even loops `_draw_images(i)` per volume (viewer.py:905-909), rebuilding all tooltips n times, and `_load_file` ends with a rebuild followed by `_on_restore` doing more redraw work (viewer.py:995-996). Replace with one `refresh(volume_index=None)` that does `set_data`/`set_extent`/label updates in place; nothing after `__init__` ever changes the number of panels.

7. **De-duplicate the zoom-sync closures and separate flag from latch.** `on_xlim_changed`/`on_ylim_changed` are copy-paste (viewer.py:212-240), and `_syncing_limits` doubles as the user-facing couple/decouple setting (viewer.py:393-395, menu item 700-702) *and* the reentrancy guard — toggling sync off is indistinguishable from being mid-sync. Split into `self.sync_limits` (setting) plus a private `_in_sync_callback` latch, one parameterized implementation. (Matplotlib's `ax.sharex/sharey` would delete all of this but cannot cleanly be un-shared at runtime, so keep the callback route while the couple/decouple menu item exists.)

8. **Collapse the Escape handler.** `on_key`'s escape branch (viewer.py:642-657) removes `text_boxes` manually (650-653), then calls `_remove_graphics()` (654) which removes them again, then re-clears `self.circles` (655) which `_remove_graphics` already did. Reduce to mode-reset + `_remove_graphics()` + `_show_message(False)`, and drive keys from a dict for testability.

9. **Remove the backend-conditional axis entirely.** `TKAGG` gates behavior in six places (viewer.py:49-57, 302-317, 708-709, 766-770, 789-793, 926-927), all frozen at import time (stale if the backend changes afterward), plus Tk-only attributes `canvas.manager.window` / `window.after` (viewer.py:768, 785, 791, 837) and the DPI-fragile pixel constant `Y_SKIP` (28 vs 50; viewer.py:50, 55 — wrong on HiDPI). Every one of these exists solely because easygui requires Tk; recommendation 5 in the next section deletes the axis. Whatever capability checks remain should be computed once at construction, not import.

10. **Retire the hand-rolled context menu.** `_make_option`/`_render_menu`/`_remove_menu` (viewer.py:998-1029) draw `fig.text` boxes at pixel offsets and hit-test `get_window_extent` against `event.x/y` (viewer.py:674-680) — the most backend/DPI-sensitive code in the file. Within matplotlib, replace with a small always-present control strip of `matplotlib.widgets.Button`s (or a keyboard-driven menu); under a Qt frontend this becomes a native `QMenu`. Until then, at minimum derive spacing from font metrics rather than `Y_SKIP`.

## Other refactor recommendations

1. **(P1, load-bearing for the cluster/headless constraint) Make `import mbirjax` GUI-silent.** Delete the import-time `matplotlib.use('TkAgg')` block and the READTHEDOCS special case (viewer.py:9-17); import no GUI toolkit at module scope (easygui at viewer.py:5 imports tkinter transitively — on a Tk-less Python, `import mbirjax` currently dies outright). Backend policy moves into `SliceViewer.__init__`/`slice_viewer`: inspect `matplotlib.get_backend()`; if non-interactive (Agg) raise a clear `RuntimeError` (or warn-and-return) instead of half-working. Module constants at viewer.py:49-57 become instance state. Acceptance test: a headless batch import and a headless `pytest` run produce zero warnings.

2. **(P1) Namespace hygiene.** Add `__all__ = ['SliceViewer', 'slice_viewer']` to viewer.py; today `from .viewer import *` (mbirjax/__init__.py:13) publishes `mbirjax.os`, `mbirjax.plt`, `mbirjax.easygui`, `mbirjax.TKAGG`, etc. (No `__all__` exists anywhere in the package — the same pass is worth doing elsewhere, but viewer.py is the worst offender because of its side effects.)

3. **(P2, load-bearing for the mbirtorch port) Make viewer.py a self-contained pure-numpy module.** Its only package dependencies are `mj.TomographyModel.convert_subdicts_to_strings` (viewer.py:114) and `mj.save_data_hdf5` (viewer.py:831); both live in jax-importing modules (tomography_model.py:1194, utilities.py:121), and the serializer additionally calls `ParameterHandler.save_params`, which also imports jax. Invert the dependency: the viewer's contract becomes "`data_dicts` are dicts of *strings*"; the mbirjax-side `slice_viewer` wrapper performs the conversion before construction (the conversion already happens exactly once, at `__init__`), and saving goes through a small local h5py writer or an injectable `save_fn`. Result: viewer.py imports numpy, matplotlib, and (lazily) h5py only, `import mbirjax as mj` (viewer.py:7) disappears along with the circular-import ordering constraint in `__init__.py`, and the identical file serves mbirtorch. Packaging: a shared micro-package is cleanest; a zero-intra-package-import single file that both repos vendor is an acceptable interim. Keep `np.asarray(dataset)` at the boundary (viewer.py:96) — it already handles jax arrays; put the torch shim (`t.detach().cpu().numpy()` for CUDA tensors, which `np.asarray` alone won't handle) in mbirtorch's wrapper, not in the viewer.

4. **(P2) Model/view/controller split, which is also the testability story.** Extract a `VolumeStack` (pure numpy, no matplotlib): input normalization (viewer.py:148-187), perm math (144-146, 406-423), slice mapping (436-448), difference/restore (841-901), ROI mask + stats (456-492), file load (944-996, 1054-1066). All of it is unit-testable headlessly on Agg — today there are **zero** viewer tests (nothing in tests/). The controller is testable too: matplotlib's own test suite drives widgets by synthesizing `MouseEvent`/`KeyEvent` and processing them through `fig.canvas.callbacks` on an Agg canvas; the consolidated dispatcher from event-recommendation 1 makes that practical. Priority tests: perm round-trips, shallow-volume slice mapping, difference shape/perm validation (861-868), the `_load_file` 4D branch (978-986), ROI stats.

5. **(P3) Decouple construction from showing; return the viewer.** `__init__` calls `self.show(block=block)` (viewer.py:139), and `slice_viewer` returns `None` even for `block=False` (viewer.py:1118-1122), which *forces* the module-global `_NONBLOCKING_VIEWERS` keep-alive (1069). Make `SliceViewer(...)` build-only, `show()` display; have `slice_viewer` return the viewer object (keep the registry as a belt-and-suspenders keep-alive for callers who drop it). The TkAgg finalizer dance (`plt.close`-by-object / `del` / `gc.collect()`, viewer.py:1129-1136 and 1031-1051) should be gated on backend == TkAgg and disappears entirely under a Qt frontend. Also fix the docstring drift: the `SliceViewer` Args block (viewer.py:74-92) omits `block`.

6. **(P3) API surface.** Keep the public `slice_viewer` signature stable — it is exercised at 40+ call sites — but stop duplicating the 10-parameter list across `SliceViewer.__init__` (94-95) and `slice_viewer` (1072-73); an internal config dataclass documented once removes the drift channel (item 5 is an instance of it). Separately, `mbirjax/preprocess/mar.py:875` opening a blocking GUI from library code at `verbose >= 2` should become an explicit `show_masks=` flag or callback — a batch MAR run at high verbosity should not hang on a window.

7. **(P4) Dead and vestigial code.** `CheckButtons` import unused (viewer.py:24); commented-out fallback (16); `_normalize_inputs` computes `_syncing_axes` (154) which `__init__` unconditionally overwrites (133), and the name is inverted at its one real use — `_toggle_decouple_slice_axes` passes `_syncing_axes` as `decoupled` (387-389); `data_dict = ()` tuple sentinel vs dict/None elsewhere (947); `chr(10)` for `'\n'` (32-36, 60-61); `_get_perm_from_slice_ind` relies on set iteration order — use `sorted({0,1,2} - {s})` (146); `on_context_select` returns a value no caller sees (682); `easygui.boxes.global_state.prop_font_line_length = 80` mutates third-party global state at construction (138); `self.datasets` is retained for the object's lifetime but never read after `_prepare_data` (96, 165-166) — drop it after init.

8. **(P4) Memory/performance notes for large volumes.** A difference image allocates a full extra volume (876-879) — fine, but document it; `vmin`/`vmax` defaults scan every voxel of every volume at open (179-182) — for 4 GB+ volumes consider sampling or a documented fast path; the `_get_mask` meshgrid cache (456-463) can be replaced by broadcasting with `np.ogrid` (no cache, no dict keyed by shape). The blitting work (refactor step 6 below) is the piece that matters for remote X.

## Suggested refactor sequence

Each step leaves the viewer fully working and demo-verifiable (`demo/demo_slice_viewer.py`, `demo/demo_10_artifacts.py` for nonblocking + multi-volume).

1. **Hygiene and latent-bug fixes (no behavior change):** `__all__`; delete dead code and the `_update_axis` dead block (424-429); `_display_mean` `continue` (478); `sorted()` perm (146); resolve the `_syncing_axes` double-init/naming (133 vs 154, 387-389); drop `self.datasets`. Verify by running two demos.
2. **Import-side-effect removal (cluster load-bearing):** move backend selection and capability detection into construction; lazy toolkit imports; instance-level constants. Acceptance: headless `import mbirjax` is silent.
3. **Extract `VolumeStack` + first headless tests (port load-bearing):** pure logic moves out behind the existing methods; add the unit tests from recommendation 4. No UI change.
4. **Event consolidation:** single button-press dispatcher, mode enum, trailing-edge stats update, single tooltip owner, in-place `refresh()` replacing rebuilds. Add synthesized-event controller tests.
5. **Delete easygui:** replace the five dialogs (intensity-range entry 302-344, data-dict text 719-756, array chooser 1054-1066, file open/save 766-839) with matplotlib-native widgets (`TextBox`, buttons) or a tiny `dialogs.py` adapter; remove easygui from pyproject.toml:45. All `TKAGG` conditionals and `window.after` scheduling vanish; Load/Save now work on QtAgg/macosx too.
6. **Blitting + slider throttling (cluster load-bearing):** cache backgrounds, blit slice and clim updates, `valstep=1`, slice-change short-circuit. Verify interactively over `ssh -Y` — this is the fix for the observed plain-X11 slider lag.
7. **De-jax the module (port load-bearing):** move data-dict serialization to the mbirjax wrapper boundary, localize the h5 save; viewer.py now imports numpy/matplotlib/h5py only. Decide packaging (micro-package vs vendored file) with the mbirtorch Phase-2 work.
8. **Optional, later:** pyqtgraph frontend behind `mbirjax[viewer-qt]`, reusing `VolumeStack` unchanged; napari as a one-line optional export.

Steps 1-6 are incremental within the current file and keep ~80% of existing code; step 7 is the gate the mbirtorch port actually needs; step 8 is where to go if the matplotlib ceiling ever binds.
